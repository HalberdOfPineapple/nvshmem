Overview A

What the example shows

A GPU kernel often builds its result in shared memory, a small, fast scratch area that belongs to one thread block. The usual way to send that result to another GPU is for every thread to load its piece from shared memory and store it across NVLink. Hopper (sm_90) and Blackwell (sm_100, your GB200) GPUs have a hardware copy engine per SM, the TMA (Tensor Memory Accelerator), that can move a whole block of bytes between shared and global memory on its own. The threads only have to start it.

This example shows the NVSHMEM API for using that engine: the block lends its shared memory to NVSHMEM (nvshmemx_give_smem), and then an ordinary-looking nvshmemx_putmem_nbi_block becomes a single bulk copy from shared memory to the peer GPU. TMA is off by default; the environment variable NVSHMEM_TMA_POLICY=ENABLE turns it on. With it off, the same code still works and falls back to per-thread copies.

Overview B

Terms used on this page

PE
Processing element: one process of the job, owning one GPU. The example uses 2 or more.
thread block / CTA
A group of GPU threads that run on one SM and can share memory and synchronise with __syncthreads(). CTA (cooperative thread array) is the hardware name. This example launches one block of 1024 threads.
warp
32 threads of a block that execute in lockstep. 1024 threads = 32 warps; warp 0 is threads 0–31.
shared memory
On-chip memory private to one block, gone when the block ends. Declared here as extern __shared__ char nvshmem_smem[]; its size comes from the third <<< >>> launch argument.
global memory
The GPU's main memory (HBM). NVSHMEM's symmetric heap, and so recv_data, live here.
TMA
Tensor Memory Accelerator: a copy engine inside each SM (sm_90 and newer) that moves bytes between shared and global memory asynchronously, started by one thread.
bulk copy
The TMA operation used here, PTX cp.async.bulk: copy n contiguous bytes. Its SASS (machine code) name is UBLKCP.
async proxy
The path the TMA engine uses to read memory. Normal thread loads and stores go through the generic proxy. Writes made through one are not automatically visible to the other; a proxy fence fixes that.
nbi
Non-blocking-initiation: the put call may return before the data has arrived. Completion is guaranteed only after nvshmem_quiet (or a barrier).
_block
The call is made by all threads of the block together, and NVSHMEM divides the work among them.
quiet
nvshmem_quiet(): wait until every put this caller started has completed at the destination.
barrier_all
Every PE waits until all PEs reach the same point; it also completes outstanding puts.
elect.sync
A PTX instruction that picks exactly one thread of a warp as leader, used so that only one thread starts the copy.
mbarrier
A small hardware barrier object stored in shared memory, used by TMA to signal "copy finished". Not needed by this example's direction of copy.
STEP 1

Start, find ranks, pick the GPU

tma-smem.cu:81-103

The program can start NVSHMEM two ways. Because the build has MPI support (NVSHMEM_MPI_SUPPORT=ON), the example is compiled with NVSHMEMTEST_MPI_SUPPORT and checks one environment variable:

  • NVSHMEMTEST_USE_MPI_LAUNCHER unset or 0 → plain nvshmem_init(), exactly as in the ring walkthrough (PMI bootstrap by default, two-stage init because the GPU is chosen afterwards).
  • NVSHMEMTEST_USE_MPI_LAUNCHER=1 → nvshmemi_init_mpi() from examples/bootstrap_helper.h:72-93. It loads Open MPI at run time (dlopen("libmpi.so.40"), line 47), calls MPI_Init, then nvshmemx_init_attr(NVSHMEMX_INIT_WITH_MPI_COMM, &attr) so NVSHMEM uses MPI's process list. The helper only works with Open MPI, because it looks up Open MPI's global symbol names.

nvshmem_my_pe() and nvshmem_n_pes() on the host just return what the bootstrap learned (src/host/init/query_host.cpp:14-16, nvshmemi_boot_handle.pg_rank / pg_size), so calling them before cudaSetDevice is fine. They do not trigger the deferred part of initialisation.

STEP 2

Ask how much shared memory NVSHMEM wants

tma-smem.cu:106, 121-124

nvshmemx_ask_smem is one inline function compiled for both host and device (__host__ __device__), so main() and the kernel call the same code. It returns constants and reads no state at all: not the TMA policy, not the GPU type.

ModeBytesMeaning
RECOMMENDED65,536Reserved area plus room for one 64 KiB copy tile; needed for the global→global staging path.
MINIMUM32,768Enough for single-buffered staging. NVSHMEM's own barrier kernel uses this.
BARRIERS_ONLY1,136Only NVSHMEM's reserved bookkeeping area. The example uses it as the offset where its own data may start.

The 64 KiB answer is larger than the 48 KiB of dynamic shared memory CUDA allows a kernel by default, so the example always takes the cudaFuncSetAttribute(..., cudaFuncAttributeMaxDynamicSharedMemorySize, 65536) branch. That call raises the per-kernel limit; without it, the launch with 64 KiB would fail.

STEP 3

Allocate, zero, and wait for everyone

tma-smem.cu:110-127

nvshmem_malloc(4096) finishes the deferred initialisation and carves a 4 KiB symmetric buffer, exactly as in step 3 of the ring walkthrough. During that initialisation, nvshmemi_init_device_state() also reads NVSHMEM_TMA_POLICY:

  • Defined at src/include/host/env/env_defs.h:404-406: values DISABLE (default), ENABLE, FORCE.
  • Parsed at src/host/init/init.cu:2160-2172 into nvshmemi_device_state.tma_policy (0, 1, 2), which the kernel later reads from constant memory. On a GPU older than sm_90, ENABLE is downgraded to off with a warning and FORCE is an error (init.cu:2197-2212).
  • If TMA is on, init allocates the registration table that step 4 writes into: one entry per (running grid, block), TMA_MAX_BLOCKS (default 4096) × 4 grids, in GPU global memory (init.cu:2232-2239).
  • With NVSHMEM_DEBUG=INFO it logs NVSHMEM TMA policy = 1 (init.cu:2215).

cudaMemset zeroes the local receive buffer, and nvshmem_barrier_all() makes sure every PE has done so before anyone starts writing into a neighbour. The host barrier runs nvshmem_quiet(), launches NVSHMEM's one-block barrier kernel on NVSHMEM's internal stream, and waits for it (src/host/coll/barrier/barrier.cpp:17-23). That kernel itself uses give_smem(…, ask_smem(MINIMUM)) and release_smem() (src/host/stream/coll/barrier/barrier.cu:17, 38), the same API this example demonstrates.

STEP 4

Lend the block's shared memory: give_smem

tma-smem.cu:45-52

The kernel is launched with 64 KiB of shared memory. NVSHMEM owns the first 1,136 bytes; the example puts its 4 KiB payload right after them.

Call chain, on the GPU
  1. nvshmemx_give_smem(smem, 65536)src/include/device/nvshmemx_defines.h:86-124 All 1024 threads call it. Compiles to nothing on GPUs older than sm_90. Returns immediately if the policy is DISABLE, the pointer is null, or the size is below 1,136. So with TMA off, nothing is registered and every later put takes the plain path.
    1. nvshmemi_tma_block_is_elected()pt-to-pt/tma_device.cuh:68-75Picks exactly one thread of the block: it must be in warp 0, and then elect.sync picks one lane of that warp.
    2. nvshmemi_tma_claim_smem_registration()common/nvshmemi_common_device.cuh:517-527That thread claims this block's entry in the registration table with an atomic compare-and-swap. The entry is chosen by the grid's hardware id (%gridid, modulo 4) and the block index. A block index ≥ TMA_MAX_BLOCKS gets no entry and silently falls back.
    3. nvshmemi_tma_publish_smem_registration()nvshmemi_common_device.cuh:545-550Writes the buffer's base address and size into the table, then __threadfence() so other threads see it; give_smem ends with __syncthreads().

give_smem does not touch the shared memory itself and does not set up any barrier objects. Each TMA path that needs mbarriers creates them when it runs (mbarrier.init at nvshmemi_common_device.cuh:817, 895, 1016-1021). The shared→global copy in this example needs none.

STEP 5

Fill the payload, then the proxy fence

tma-smem.cu:55-63

Each thread tid writes mype * 1000 + tid into payload[tid], so PE 1 writes 1000, 1001, … 2023. __syncthreads() waits until all 1024 writes are done.

Those writes are ordinary stores, which go through the generic proxy. The TMA engine reads shared memory through the async proxy, and the hardware does not keep the two in sync automatically. Without the fence, the copy engine could read stale bytes.

NVSHMEM leaves this fence to the caller. The contract is written at src/include/non_abi/device/pt-to-pt/tma_device.cuh:304-308: "The caller must issue fence.proxy.async.shared::cta before calling this function … Without this fence, the TMA engine may read stale data." Every thread executes it, and nvshmemx_putmem_nbi_block begins with another __syncthreads(), so the thread that starts the copy has seen everyone's writes.

STEP 6

Put 4 KiB to the next PE: nvshmemx_putmem_nbi_block

tma-smem.cu:66-67

All 1024 threads call the put with the same arguments. The destination recv_data is this PE's own symmetric address; NVSHMEM translates it to the peer's copy, as in the ring example.

A shared-memory source cannot go over the network

If the peer is on another node without NVLink access (the proxy/InfiniBand path from the ring walkthrough), the CPU proxy thread and the network card would have to read the source buffer, and neither can read an SM's shared memory. NVSHMEM does not stage it through global memory. Instead the host proxy looks for a registered buffer and asserts: "SM shared memory and registers are not supported" (src/include/internal/host/nvshmem_internal.h:154-158); the IBGDA path has assert(0) (ibgda_device.cuh:2006-2007). Your build is a release build compiled with -DNDEBUG, which removes assert, so in that case the program would not stop with a clear message; the behaviour would be undefined. Use this pattern only when the peer is NVLink-reachable.

STEP 7

Wait for the copy, then give the memory back

tma-smem.cu:68-74

Call chains, on the GPU
  1. nvshmem_quiet()src/include/device/nvshmem_defines.h:736-738Called by thread 0 only.
    1. nvshmemi_quiet<THREAD>()common/nvshmemi_common_device.cuh:1185-1212
      1. nvshmemi_tma_drain_if_registered():576-587If this block registered shared memory: commit_group + wait_group 0, i.e. wait for all bulk copies issued by the calling thread.
      2. __threadfence_system():1185-1212On the NVLink-only path: make the completed writes visible system-wide. On a network path it calls nvshmemi_transfer_quiet instead.
  2. nvshmemx_release_smem()src/include/device/nvshmemx_defines.h:136-152 One elected thread clears this block's base and size in the table, fences, and resets the owner with atomicExch (nvshmemi_common_device.cuh:552-558). The next kernel that lands on this table entry starts clean. It does not wait for TMA copies; that is quiet's job.
Why thread 0 calling quiet is enough, and why that is fragile

TMA copy groups are tracked per thread, and wait_group only waits for the calling thread's groups. The copy was issued by the elect.sync leader of warp 0; quiet is called by thread 0. They are the same thread only if the hardware elects lane 0. With all 32 lanes active that is what happens in practice, and the example passes. But NVSHMEM's code does not force it: a different part of NVSHMEM, the global→global block copy, deliberately hard-codes its issuing threads (is_load = (tid == 0); is_store = (tid == warpSize);, nvshmemi_common_device.cuh:1008-1012) instead of using elect.sync. The in-repo test test/device/pt-to-pt/tma_smem.cu:52-58 uses the same thread-0 pattern as this example.

STEP 8

Check the result and clean up

tma-smem.cu:132-160

cudaDeviceSynchronize() waits only for this PE's kernel. The comment at lines 133-135 explains the second nvshmem_barrier_all(): the neighbour sending to this PE may still be running, and only the barrier guarantees every PE's put has landed. Each PE then copies recv_data to the host and checks host[i] == prev_pe * 1000 + i, where prev_pe = (mype − 1 + npes) % npes. nvshmem_free and nvshmem_finalize work as in the ring walkthrough; in the MPI mode, nvshmemi_finalize_mpi() then calls MPI_Finalize.

Overview E

Surprises in the trace

  • TMA is off unless you ask. The example's header comment says to set NVSHMEM_TMA_POLICY=ENABLE; without it the program still passes, but through per-thread copies, so it demonstrates nothing about TMA.
  • ask_smem is a constant table. It never looks at the policy or the GPU, which is why the host can call it before initialisation finishes.
  • One copy for the whole block. The 4 KiB are sent as a single cp.async.bulk by one thread; there is no splitting into chunks and no minimum size.
  • quiet from thread 0 relies on lane 0 being elected. See step 7.
  • The payload sits where NVSHMEM would stage global→global copies. That is safe here only because every put in this kernel has a shared-memory source. A put from global memory in the same kernel would use the region starting at byte 1,136 and overwrite the payload. This is a reading of the code (staging buffer at nvshmemi_common_device.cuh:947-948, 994), not a documented rule.
  • Documented minimum vs enforced minimum. The comment above give_smem (nvshmemx_defines.h:84) asks for at least 32 KiB; the code only rejects sizes below 1,136 bytes.
  • Shared-memory sources are NVLink-only. Across a network path the put is unsupported, and in a release build the guarding assert is compiled out (step 6).
  • A related gap outside this example. For a global-memory source, the block put's outgoing bulk copies are issued by thread 32 (tid == warpSize), and a later nvshmem_quiet() from thread 0 would not wait for them. Found by reading nvshmemi_common_device.cuh:1008-1012 and 1077-1079; not verified by a run.
